# Approval Rules

Link Approvals checks the binding between an owner response and one reviewed effect. It performs no storage, delivery or execution and depends only on the shared interaction contract and generic packages.

## Review and Decision

An authorization request requires one confirmation, a source-owned operation reference and a complete review whose digest matches the operation. The review describes capability, targets, lifetime and exact technical scope. The source derives these facts from its actual operation. Requester intent and untrusted tool hints cannot certify a narrower capability. Reply-only questions never enter permission states.

## Single-Use Claims

The engine serializes eligibility checks and claim consumption. Eligibility requires an authorized, unclaimed decision before its deadline, the exact operation binding and fresh source evidence for authority, generation and controls. A pure eligibility result alone is no execution permit. Run grants, configuration changes and held operations are distinct scopes, each applied once through its source.

## Qualifications and Outcomes

A positive confirmation with additional user text cannot automatically release the frozen operation. It requires clarification or a narrower fresh review. Denial, dismissal, expiry and revocation leave the gate closed. A source reports applied, failed or unknown only against its matching claim. Losing the outcome cannot authorize another claim or replay an uncertain external effect.
