# Interaction Decisions

Interaction coordination shares one typed lifecycle while hosts and resource sources retain execution authority. These boundaries keep answers, control intent and observed execution distinct.

## Four Libraries

The contract owns shared wire types, Link Approvals computes authorization rules, Link Controls computes work-control rules, and Link Interactions commits their state and durable events. Rule libraries perform no delivery or execution. The coordinator runs inside existing trusted hosts and adds no service or command.

## Answers and Execution

Information answers return exact selections, skipped items and user text to their original caller. Permission answers can authorize only a frozen source-owned operation. A source rechecks its independent grants and current work before claiming execution once. Qualified permission answers require clarification. Existing policies continue deciding when to ask; ordinary file helpers never introduce interaction policy.

## Review and Provenance

Permission views derive meaning, target, lifetime and consequences from typed resource data. Exact syntax supports that review without replacing it. Results distinguish supplied option wording from owner-authored text and automatic fallback. Request IDs identify records; separate owner-only codes target responses without becoming authentication credentials.

## One Decision Store

All surfaces submit through one protected transaction and immutable question revision. Editable drafts and recommendations create no authority. First acceptance closes every presentation, including a native dialog. Unsupported controls use a full standalone form rather than weakening the requested scope. The versioned store reads no legacy approval files or callbacks.

## Host and Source Boundaries

The host retains conversations, checkpoints and lineage. Sources retain payloads and actual effects. Host-issued bindings and control revisions fence stale model calls, including calls already allowed by policy. A shared dispatch fence orders source admission against controls but never spans an owner wait. A lost outcome remains Unknown until its original source reconciles it.

## Retained Work

Pause preserves progress and blocks follow-on work at the declared boundary. Stop requires explicit resumption; archive and deletion are separate operations. Holds restrict delegation without requiring the coordinator to stop designing. Releasing a hold requires current-plan revalidation. Tree controls freeze their exact members and retain per-member outcomes.

## Scheduling and Delivery

Existing schedule definitions and occurrence identities remain the source of timing and firing ownership. Each admitted occurrence has its own work binding. A retained child keeps its task, lineage and result destination. Durable result receipts and delivery identities permit redelivery without repeating the parent input or uncertain source effects. Explicit deletion waits for each owning store to acknowledge its scope.
