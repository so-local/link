# Interaction Security

Interaction authority depends on trusted source and owner ingress adapters around a private machine store. The engine validates typed bindings and coordinates decisions while resource owners enforce actual execution.

## Trust Boundaries

Models supply ordinary question proposals, never privileged domains, owner identities, response codes or execution effects. Host adapters bind source, original tool call and exact work. Owner transports authenticate before submitting a response. Local hosts name the authenticated owner of this machine store `owner`, an actor beside the principals Link mints, since no identity source vouches for that person yet.

### Actors

Saved and sent, an actor says its kind: `{ kind = "owner" }`, or `{ kind = "principal", principal = "service:<id>" }`. A response code is a target hint, never an authentication credential.

## Source Enforcement

The resource source keeps its immutable payload and independent policy checks. It serializes fresh generation, resource and control evidence with claim and dispatch. The engine's transaction cannot make arbitrary remote execution atomic. A claimed effect that disconnects remains uncertain and cannot automatically replay. An approval never relaxes kernel confinement or overrides an independent grant.

### Work Credentials

Host work credentials use secret values with redacted diagnostics and constant-time equality. Only protected coordinator storage and trusted source metadata carry their bytes. They never appear in question results or owner review text.

### Registered Callers

A schedule definition alone grants no runtime authority. Once a host admits runtime work, calls for that agent require authenticated bindings even after its last work is deleted. Independent sources that have never registered runtime work retain their existing policy.

### Existing Policy

Source calls allowed by existing policy retain the same host binding, control revision and execution tracking without prompting. Dropping host metadata cannot turn a controlled call into an independent request. A source observer retains dispatched calls after a client disconnects and settles the original outcome. Unknown outcomes keep stop and restart fenced until reconciliation.

## Private State

The store uses private files, no-follow reads, directory locks and durable atomic writes. Shared observations keep the same version, size and no-follow checks. Mutations and deadline resolution keep the exclusive lock and durable commit. Corrupt, unknown-version, linked or full state is refused. State stays outside runtime mounts. Terminal records and code reservations consume bounded capacity and are not imported from older approval stores. Displayed review is complete, and invisible control characters are rendered visibly.
